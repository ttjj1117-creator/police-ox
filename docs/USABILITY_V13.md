# v1.3 사용성 패치

2026-11-05 · Asia/Seoul. 기준 main은 `7473122a7d27e858a7884195a98527c1d292dc1a`다. 기존 강사 해설·계정 동기화·해설 크기 제한 해제 정책을 보존하는 화면·입력 패치다.

## 확인한 원인과 변경

1. `OriginalApp.tsx`의 이동 버튼이 긴 해설 뒤에 있었다. DOM 순서를 문제·제출/채점 → 이전·다음 → 두 해설 형식으로 바꿨다. 이동 조건·핸들러는 유지하고 필기 면에 버튼·해설을 넣지 않았다.
2. 일반적인 Chromium 펜 탭은 기준 코드에서도 정상 동작했다. 별도로 버튼 안에서 눌렀다가 4px 움직여 바깥에서 끝내도 pointer capture가 up/click을 버튼으로 보내 선택되는 오류를 재현했다. `InputGuard.tsx`와 `InkChoiceButton`에서 끝점의 실제 버튼·경계를 확인한다. 같은 활성 버튼에서 시작·종료한 유효한 trusted 펜 탭에만 누락된 click을 보완한다. 기본 click을 먼저 기다리고 후속 click은 접촉별로 중복 차단한다. 비활성 시 시작/종료한 탭은 나중에 활성화돼도 실행하지 않는다. 물리 Samsung S펜에서 click이 누락되는 원인은 확정하지 않았다.
3. 풀이의 `touch-action: pinch-zoom`은 확대를 허용했다. 내부 scope는 접촉 전부터 `none`, 바깥 여백은 `pan-y`로 준비한다. 내부 한 손 이동·그림/표의 가로 이동은 기존 수동 pan, 여백의 세로 이동은 네이티브 경로를 유지한다. 실제 펜 접촉 중 무효화한 손은 해당 접촉 종료까지 무효이며 새 정상 손은 바로 사용할 수 있다.
4. 필기 배치는 정확한 기존 서명을 유지하면서 본문·스타일·폭·폰트·이미지 등 실제 무효화에만 측정한다. 측정 결과를 공유하고 완료 획의 경로·필압 계산을 재사용한다. ResizeObserver는 그리기 전 배치를 확인한다. 측정된 키와 React가 반영한 키를 구분해 이전 키로 새 좌표를 저장하지 않는다. 일시적으로 측정할 수 없어도 기존 필기를 빈 문서로 저장하지 않고 원래 배치로 복원한다.
5. 답안표는 현재 세션·문항 스냅샷의 저장된 Attempt 결과만 한 번 인덱싱한다. 공개 정답은 기존 초록, 오답은 비슷한 밝기의 차분한 붉은색, 모르겠음은 별도 중립색이다. 미제출 모의고사는 응답 여부만 중립 표시한다. 현재 문항은 outline으로 구분해 오답 배경을 덮지 않는다. 접근성 이름에 결과·현재 위치·검토 상태를 더했고 닫힌 답안표의 버튼은 생성하지 않는다.

`QuizChrome.tsx`의 시간 표시만 갱신하도록 분리했다. 기존 절대 deadline 검사·500ms 만료 감시·focus/visibility 복귀·저장 실패 재시도는 그대로다. 답안·획의 원자적 저장, 이동 직전 flush, 기존 스냅샷·세션·시도 규칙은 바꾸지 않았다.

## 실제 성능 비교

동일한 중립 시연 문항 28문단·강사 해설 80문단·완료 획 40개×50점을 사용했다. Chromium `136.0.7103.25`, CSS `1280×800`, 개발 StrictMode, CPU 제한 없음. 임시 AST 계측과 Range/스타일 호출 계측을 사용했으며 계측 코드는 앱·번들에 넣지 않았다. 각 시간은 동기 함수 실행의 포함 시간이라 서로 더해 전체 CPU 시간으로 해석하면 안 된다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 4초 대기 중 OriginalApp 실행 | 16회 / 89.1ms | 0회 |
| 같은 대기 중 정밀 배치 측정 | 16회 / 18.2ms | 0회 |
| 같은 대기 중 Range 조회 | 1,088회 | 0회 |
| 같은 대기 중 완료 획 경로 계산 | 640회 | 0회 |
| 다음 버튼→새 문항 표시 중앙값, 5회 | 160.0ms | 103.9ms |
| 제출 버튼→저장된 결과 표시 중앙값, 5회 | 168.8ms | 133.0ms |
| 손 이동 처리 60회 누적 | 6.1ms | 5.8ms |

다음/제출 시간은 Playwright 조작부터 DOM 표시까지의 왕복이며, 사전 scrollIntoView는 제외했다. 손 이동의 작은 차이는 유의미한 개선이라고 주장하지 않고 기존 경로를 유지했다. 개발 StrictMode는 렌더를 반복하므로 운영 환경의 절대 횟수·시간과 같지 않다. 이 수치는 물리 S펜 입력 지연·프레임 속도·사용자의 실기기 체감 검사를 대체하지 않는다.

## 검사와 보존

중립 자료와 독립 Chromium 저장 영역을 사용한다. 실제 사용자 문제·해설·학습·필기·계정을 초기화하지 않았다.

- 실제 브라우저가 생성한 펜 down/up/click으로 번호·제출·이동·필기 왕복을 확인했다. 바깥 종료·드래그·취소·획의 버튼 통과·손바닥을 거부하고 새 펜·손·마우스·키보드를 유지한다. click 누락 보완 검사는 실제 down/up 뒤 UA click 한 번만 의도적으로 억제해 확인한다.
- 두 손가락 touch 입력으로 중립 페이지가 실제 확대되는 양성 대조군을 먼저 확인했다. 같은 입력의 풀이 내부·여백 핀치와 연속 탭에서 scale 1을 유지하고 세로/지역 가로 이동·필기를 보존했다. 이 환경에서 `synthesizePinchGesture`의 touch 옵션은 중립 페이지에도 반응하지 않아 확대 차단 증거로 사용하지 않았다. `setPageScaleFactor`도 초기화 외에는 쓰지 않았다.
- 동일 크기의 스타일 변화, 일시적 측정 불가, 외부 stylesheet의 ResizeObserver 전환, 기존 배치 복귀·실행 취소·새로고침·이동 저장을 검사한다. 기존 배치 키·좌표·paper 및 body/choice 필기 문서 형식은 유지한다.
- 현재 세션 정답/오답/모르겠음/미제출, 현재 오답과 검토 표시, 과거 세션과의 격리, 시험 제출 전 결과 비공개, 두 해설 앞 DOM 순서를 검사한다.
- 기존 계정/real-demo·원문/OX/해설 동기화·오프라인/충돌·백업·종료 확인·타이머 회귀를 함께 실행한다. 서버 SQL/RLS·해설 규약·크기 제한·문항 ID·공식 정답·분류·채점 버전·저장소·PWA origin은 변경하지 않는다.

정해진 npm 스크립트의 동일 진입점을 설치된 Node로 실행했다: `vitest/vitest.mjs run` **430개 통과**, `typescript/bin/tsc -b`, `tsc -p tsconfig.tools.json`, `VITE_BASE_PATH=/police-ox/ vite/bin/vite.js build` **통과**, `scripts/run-e2e.cjs --reporter=line,json` **78개 전체 한 번에 통과(3.6분)**. 새 입력/배치/사용성 검사는 각각 4/3/5개다.

첫 병렬 실행의 기존 CLI 5초 제한 초과는 단독 전체 실행으로 재확인해 통과했고 제한이나 단언을 바꾸지 않았다. 기존 답안표 검사의 이전 exact 이름은 새 접근성 상태를 포함하는 접두어 선택자로 맞췄다. 해설 동기화 검사의 간헐적 종료 지연은 원본 조건으로 3회 연속 및 최종 전체 실행에서 통과해 앱·동기화 코드를 바꾸지 않았다. 최종 배포 식별자는 배포 후 기준 앱의 이 문서와 연결 PR에 기록한다.

## 사용과 배포

기존 주소 https://ttjj1117-creator.github.io/police-ox/ 와 `.github/workflows/deploy-pages.yml`을 유지한다. 공개 코드·관련 테스트·문서만 반영하고 개인 자료·환경 값·계측/테스트 산출물은 반영하지 않는다. 해당 커밋의 새 Actions build/deploy 성공과 공개 파일의 최종 빌드 일치를 확인한다.

기존 문제·해설을 다시 가져오거나 브라우저 데이터를 지울 필요가 없다. 진행 중 풀이를 마친 뒤 ‘앱 업데이트 적용’을 누른다. 필기는 계속 이 기기에 저장하며 기존 일반 백업·기기 동기화의 범위는 바꾸지 않는다. 물리 Galaxy Tab S11/S펜과 운영체제 전체 확대는 직접 검증하지 않았다.

입력 기준은 [Pointer Events](https://www.w3.org/TR/pointerevents3/), 접촉 전 제스처 정책은 [touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)을 참고한다.

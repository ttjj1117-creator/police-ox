# 빈출 쟁점 자료와 배포

기존 ‘근거·출제 빈도’ 메뉴에서 과목·기존 단원·시험·연도·회차로 학습 쟁점과 관련 기출을 탐색한다. 바로 풀기는 기존 학습 세션을 사용한다. 개인 오답은 현재 계정의 기존 풀이 기록으로 계산한다. 진행 중 모의고사는 이 화면의 쟁점·정답·근거를 공개하지 않는다.

원문 검증 쟁점과 근거, 강사 인용 출처, 직접 대조한 학습 쟁점을 각각 표시한다. 인용 출처 연결만으로 학습 쟁점이나 법률 검증 상태를 확정하지 않는다. 원본 키와 회차·정확한 대상 위치의 집합으로 집계하며 문항 전체 연결은 지문 수를 늘리지 않는다.

읽기 화면은 같은 연결 자료의 검토 이유·기존 검증 발췌·현재 강사 문단을 참조한다. 구조화된 핵심 정리·조건·예외 본문이 없으면 미등록 상태를 표시한다. 사용 중 새 해설을 생성하지 않는다.

## 자료 전달

연결 파일은 별도 `police-frequent-issues-handoff` 1.0.0 계약으로 검사한다. 기존 문제와 두 해설 가져오기 형식을 변경하지 않는다. 설정의 ‘빈출 쟁점 연결 자료’에서 파일을 가져올 수도 있다.

로그인 계정의 연결 자료는 `police-original-frequent-issues` IndexedDB에 보관하고 기존 비공개 버킷의 `<계정 UUID>/real/frequent-issues/` 아래 불변 조각으로 동기화한다. 이전 앱은 기존 해설 경로와 묶음을 계속 사용한다. 빈 자료·낮은 원천 버전은 정상 자료를 지우지 않으며 같은 버전의 다른 내용은 충돌로 보존한다. 인계 자체의 별도 수정 버전은 제공되지 않아 동일 원천 버전의 서로 다른 연결 파일은 자동 선택하지 않는다.

승인 학습자 자동 전달은 기존 비공개 `police-ox-shared` 버킷을 사용한다.

1. `supabase/migrations/202611260001_frequent_issues.sql`을 적용한다. 기존 승인 조건과 읽기 전용 제한을 유지하면서 아래 두 경로만 추가한다.
2. `node node_modules/tsx/dist/cli.mjs scripts/package-frequent-issues.ts <connections.json> <비공개 출력 폴더>`를 실행한다. 실제 자료는 공개 Git에 추가하지 않는다.
3. 생성된 `frequent-issues/releases/<해시>/connections.json.gz`를 같은 경로로 먼저 업로드하고, 마지막에 `frequent-issues/current.json`을 업로드한다. 기존 문제·해설의 `current.json`은 이 작업에서 사용하지 않는다.
4. 새 앱의 빈 연결 저장소가 승인 학습자 로그인 후 자료를 받아 오프라인에 저장한다. 이후 개인 동기화는 기존 자동 동기화 작업에서 처리한다.

모든 연결은 현재 원문·채점 버전·fingerprint·selector와 현재 해설 레코드·출처·인용 구간을 다시 확인한다. 기존 법률 검증 상태는 유지한다. 태블릿 실기기 입력과 성능은 별도로 확인해야 한다.

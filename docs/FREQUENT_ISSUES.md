# 빈출 학습 쟁점과 비공개 배포

‘빈출 쟁점’에서는 선택한 과목의 의미 확인된 학습 쟁점을 하나의 목록으로 비교한다. 원문·강사 해설 등 출처 종류를 선택하지 않는다. 같은 과목·분류 수준에서 고유 출제 문항 수→반복 회차→최근 출제 순으로 비교하며 개인 오답·미풀이는 별도 지표다. 별칭 검색과 기존 단원·시험·연도·회차 필터를 유지한다.

관련 기출에서 원문을 확인하거나 기존 학습 세션으로 바로 풀 수 있다. 넓은 화면은 목록과 상세가 각각 스크롤되고, 좁은 화면은 돌아가기로 목록 위치·페이지·필터를 복원한다. 진행 중 모의고사의 답 공개 규칙과 임시 필기는 기존 동작을 유지한다. 출처·보류·검증 현황은 상세에서 확인한다. 정리집 없이도 빈출·관련 해설·풀이가 작동하며, 빈 정리 패널이나 자동 생성한 해설을 제공하지 않는다.

## 계약과 집계

정확한 필드·유효 예·검증 명령은 [데이터 계약](FREQUENT_ISSUES_DATA_CONTRACT.md)에 있다. 기존 엄격한 `police-frequent-issues-handoff` 1.0.0 읽기와 기존 쟁점 ID를 보존한다. 1.1.0은 명시적 분류 수준·별칭·단원 연결과 `handoffRevision`을 제공한다. 같은 원천의 분류만 달라지면 인계 수정 버전을 증가시킨다. 같은 버전의 다른 내용 또는 엇갈린 원천/분류 버전은 충돌로 기존 자료를 보존한다. 빈 자료와 낮은 버전도 정상 자료를 지우지 않는다.

의미 확인은 판례·조문 인용 식별 및 현행 법률 검증과 별개다. 인용이 없거나 식별 보류여도 실제 원문 또는 매칭된 해설 문단으로 확인한 의미 연결을 사용할 수 있다. 미확정 의미 연결은 순위에서 제외한다. 문항·채점 버전·fingerprint·selector·expectedText·해설 문단·출처 위치와 내용을 대조한다. 문항 전체 연결은 문항 수에 포함하고 지문 수는 만들지 않는다. 여러 출처가 같은 문항·대상을 가리키면 중복 집계하지 않는다.

## 개인 자료와 승인 학습자 공유본

연결 자료는 `police-original-frequent-issues`의 계정/real/demo별 IndexedDB에 보관한다. 개인 동기화는 기존 비공개 버킷의 `<계정 UUID>/real/frequent-issues/` 불변 조각·목록 경로를 사용한다. 문제·정답·해설·학습 기록 저장 경로를 대체하지 않는다. 계정 전환 중 늦은 응답은 적용하지 않으며 실패한 전송은 재시도한다.

승인 학습자 자동 전달은 기존 비공개 `police-ox-shared` 버킷의 빈출 전용 경로를 사용한다. 빈 연결 저장소는 로그인 후 공유본을 받는다. 이전 공유본을 이미 받은 저장소는 보관된 공유 마커와 실제 내용의 정확한 fingerprint를 재확인해, 코드에 승인된 공유본 순서로만 갱신한다. 최종 공유본에 도달하면 반복 내려받지 않는다. 공유 갱신 도중 개인 가져오기·개인 수신·로컬 계정 귀속이 발생하면 개인 자료를 우선 보존한다. 개인 가져오기는 기존 버전 병합 규칙을 따른다.

## 운영 교체 순서

1. 계약 CLI로 최종 연결 파일과 정확한 원문·기존 해설·강사 해설을 대조한다. 데이터 담당의 별도 집계와 앱 집계를 비교하고 해시·분류 범위·보류 내역을 비공개 인계에 보관한다.
2. 새 규약과 승인된 공유본 갱신을 지원하는 앱 코드를 기존 GitHub Pages에 배포한다. 오래된 앱과 진행 중 풀이에 강제 새로고침을 요구하지 않는다.
3. 앱 폴더에서 `node node_modules/tsx/dist/cli.mjs scripts/package-frequent-issues.ts <connections.v1.1.json> <비공개 출력 폴더>`를 실행한다. 이 도구의 구조 검사는 1번의 원천 대조를 대신하지 않는다.
4. 생성된 `frequent-issues/releases/<해시>/connections.json.gz`를 먼저 업로드하고 서버에서 다시 받은 바이트·SHA-256을 확인한다. 마지막에 `frequent-issues/current.json`만 교체한다. 이전 불변 릴리스를 보존한다. **문제·해설용 버킷 루트의 `current.json`과 개인 기록 경로는 변경하지 않는다.**
5. 빈출 목록과 압축 파일을 다시 내려받아 해시/버전을 대조하고, 승인 학습자·비로그인 접근 경계와 운영 앱의 실제 자료 수신을 확인한다. 운영 로그인을 확인하지 못했으면 그 한계를 남긴다. 단순 Storage 업로드 성공을 기기의 수신 완료로 간주하지 않는다.

최초 설치에 필요한 `supabase/migrations/202611260001_frequent_issues.sql`은 기존 승인 학습자·비공개·읽기 전용 경계를 유지한다. 이미 적용된 운영 프로젝트에서는 경로와 권한을 재사용하며 새 공개 권한이나 버킷을 만들지 않는다. 실제 문제·해설·연결 JSON, 개인 자료와 비밀 키를 공개 Git에 포함하지 않는다.

기존 앱은 1.1.0을 자동 변환해 읽지 않는다. 앱 업데이트 후 새 공유본을 받을 수 있으며, 진행 중 세션 때문에 업데이트가 보류되면 정상 종료 뒤 기존 업데이트 흐름을 따른다. 이미 받은 새 자료를 낮은 자료로 되돌리지 않는다. 잘못된 분류의 정정은 검토한 내용으로 인계 수정 버전을 증가시키고 새 승인 fingerprint로 배포한다.

후속 정리집은 선택 자료로 쟁점 ID·근거 참조·내용 해시/버전·정리본 버전/검토 상태를 연결한다. 본문 작성·편집기·전용 페이지는 별도 작업이며 [다음 단계 인계](DATA_CODEX_HANDOFF.md)에 기록한다. 물리 갤탭·아이패드의 펜 입력 확인은 자동화 viewport 검사와 구분한다.

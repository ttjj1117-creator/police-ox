# 경찰 기출 프로그램 공통 규격 v1.0.0

## 1. 이번에 확정한 제품 범위

PC에서 사용하는 개인용 학습 웹앱이다. 현재 과목은 헌법·형사법·경찰학이다. 원래 기출 문항을 통째로 보존하여 단원별, 회차별, 오답별, 모의고사 형식으로 푼다. 새 문제·새 선택지·새 정답·해설을 생성하지 않는다.

첫 구현의 채점 기준은 출제 당시 공식 최종 정답이다. 법 개정에 따른 현행 재판정이나 해설 작성은 이 원문 객관식 기능의 전제 조건이 아니다. 원문이 ㉠㉡ 보기형, 개수형, O/X 조합형이어도 원래 네 선택지 중 하나를 고르는 문항 단위로 유지한다. 이를 별도 OX 지문으로 자동 분해하거나 개별 명제의 정답을 추론하지 않는다.

최초 목표 기능:
- 단원별·연도별·회차별 원문 객관식 풀이
- 오답·모르겠음·다시 보기 복습
- 한 회차의 원문 문항을 원래 문항번호 순으로 푸는 기능
- 기존 기출 문항을 공식 영역별 목표 수로 선별한 100문항·100분 모의고사
- JSON 가져오기와 검증, 기록 저장, 이어 풀기, 백업·복구

## 2. 두 Codex의 책임

프로그램 Codex는 이 규격의 가져오기·검증·풀이·채점·기록·편성을 구현한다. 실제 시험지 OCR과 법률 정답 분석은 하지 않는다.

기출 데이터 Codex는 시험지·공식 최종 정답지에서 원문 문항과 정답을 정확히 연결한다. 추출·원문 대조·정답표 대조를 끝낸 뒤 단원 분류를 수행한다. 두 단계는 같은 Codex에서 순서대로 수행할 수 있으나 추출 중간 파일에 추정 분류를 섞지 않는다.

두 작업은 이 규격과 03·04·05번 JSON 파일을 공동 기준으로 사용한다. 구현 편의상 필드·ID·단원 코드를 임의로 바꾸지 않는다. 변경이 필요하면 기존 계약을 유지한 상태에서 변경 사유와 영향을 인계 문서에 적는다.

## 3. 기존 앱과의 관계

확인한 실제 앱 경로:
C:/Users/INTEL/Documents/Codex/2026-09-19/x20/outputs/police-ox

기존 앱은 React/TypeScript/Vite 기반이다. 기존 OX Dataset은 schemaVersion: 1, items, judgments 등의 형식이며 여기서 정한 원문 문항 교환 형식과 다르다. 같은 schemaVersion 숫자로 형식을 추정하지 않는다.

신규 형식 판별자는 format: "police-original-questions", schemaVersion: "1.0.0"이다. 신규 데이터는 별도 parser·도메인·저장소로 추가하고 기존 OX 가져오기·UUID·학습 기록을 유지한다. 기존 OX 스키마의 해설·법률근거 필수값을 가짜로 채워 신규 문항을 끼워 넣지 않는다.

기존 원문 참조 ID인 const_2026_2_1 등을 신규 원문 문항의 ID로 사용할 수 있다. 기존 OX 개별 지문 ID인 const_2026_2_1_1 등은 계속 그 지문을 가리킨다. 원문 문항 정답으로 OX 정답이나 학습 완료 상태를 자동 환산하지 않는다.

## 4. JSON 파일과 문항 ID

03번 JSON Schema가 자료형·필수필드·기본 구조의 기준이다. 아래 의미 규칙과 07번 검증 기준도 함께 구현해야 한다.

파일 단위 필드:
- format: police-original-questions
- schemaVersion: 1.0.0
- packageId: 파일 묶음 식별자. 순경 헌법 2026년 2차의 권장값은 po_2026_2_const
- packageVersion: 해당 묶음의 양의 정수 버전
- exportedAt: 시간대가 명시된 ISO 8601 시각. 저장은 UTC를 사용
- dataKind: real 또는 demo. 실제/시연 저장 영역을 섞지 않음
- stage: extracted 또는 classified
- unitRegistryVersion: 1.0.0
- questions: 원문 문항 배열
- assets: 필요한 그림의 PNG/JPEG 원본 발췌 이미지 배열

순경 공채 문항 ID:
헌법 const_연도_회차_문항번호
형사법 crim_연도_회차_문항번호
경찰학 police_연도_회차_문항번호

예: const_2026_2_1, crim_2026_2_40, police_2026_2_7

연도는 공식 시험명에 표시된 연도, 회차는 "1", "2" 같은 숫자 문자열, 문항번호는 과목 안의 원문 번호이다. 앞자리 0은 붙이지 않는다. 모의고사에서 37번으로 재배치해도 원문 ID는 바꾸지 않는다.

source.examCode는 po(순경 공채), lieut(경위 공채), demo(기능 시연)이다. 경위 문항은 lieut_const_2026_75_1처럼 lieut_를 앞에 붙여 순경 ID와 충돌하지 않게 한다. 경위의 year·round 값은 실제 공고·시험지 식별자에 따라 입력하며 위 숫자들은 형식 설명용이다. 경위 시험 편성은 이번 버전에서 비활성이다.

실제 문항에는 const/crim/police/crime/civil 접두사와 subjectId가 일치해야 한다. 미래 과목의 subjectId는 criminology, civil_general로 예약하되 첫 버전에서 실제 풀이·모의고사 대상으로 활성화하지 않는다. 시연 문항은 demo_const_1 같은 별도 ID만 사용한다.

source의 examCode·year·round·questionNumber, 문항 subjectId로 ID를 다시 계산하여 일치를 검사한다. 이 식별 정보를 수정해야 한다면 일반 내용 갱신으로 ID를 갈아끼우지 말고 명시적인 정정·이전 작업으로 처리한다.

한 과목 단위 또는 10~20문항씩 나누어 파일을 전달해도 같은 문항은 항상 같은 ID를 쓴다. 글로벌 단일 datasetId 일치를 요구하지 않고 문항 ID와 revision으로 병합한다.

## 5. 원문 표현과 그림

body는 원문에 나온 순서대로 content block을 둔다. text는 발문·조건·사례·독립 제시문을, statements는 ㉠㉡ 또는 ㄱㄴ 등의 보기 목록을, image는 원본 그림·표 발췌를 나타낸다. choices에는 number 1·2·3·4가 각각 한 번씩, 원문 순서로 들어간다. 각 선택지도 같은 block 형식을 사용한다.

발문과 독립 사례를 임의로 요약하지 않는다. 보기형 문항의 개별 보기와 조합 선택지를 혼동하지 않는다. 여러 문항이 같은 사례를 공유하면 각 문항이 단독으로 풀릴 수 있도록 그 사례를 해당 body에 포함한다. 같은 문항 안에 rawQuestionText와 구조화 body·choices를 중복 저장하지 않는다.

표나 도형이 의미를 갖는 경우 원본 부분 이미지를 assets에 보존한다. 이미지 자산은 assetId, mimeType, sha256, base64를 갖는다. image block은 assetId만 참조한다. AI로 그림을 재생성하지 않는다. 외부 이미지 URL·임의 로컬 경로·HTML·SVG 스크립트를 실행하지 않는다. 파일을 못 읽거나 필요한 그림을 보존하지 못했다면 textStatus를 hold로 두고 원문 확인이 끝난 문항처럼 출제하지 않는다.

source.questionPdf에는 원본 시험지 파일명과 실제 PDF 페이지 번호(1부터 시작)를 적는다. source.answerPdf에는 정답지 파일명·페이지와 대조한 과목 열 이름을 적는다. 교재 본문 쪽수와 시험지 PDF 페이지를 혼동하지 않는다. 데이터에 근거 파일을 내장할 필요는 없으며 파일명·위치 참조를 보존한다.

일반 텍스트 렌더링과 줄바꿈 보존을 사용한다. 선택지 순서를 바꾸지 않는다. 원문 안의 정답 판단에 영향을 줄 수 있는 부정 표현·기호·수치·괄호를 자동 교정하거나 요약하지 않는다.

## 6. 공식 정답과 출제 자격

officialAnswer.status:
- final: 공식 최종 정답
- provisional: 가답안
- missing: 정답 미확인
- demo: 시연 전용 정답

officialAnswer.kind:
- single: 정답 선택지 1개
- multiple: 공식 복수 정답으로 인정되는 선택지 2~4개
- all_correct: 전원 정답 등 특별 처리
- excluded: 출제·채점 제외 등 특별 처리
- unresolved: 미확정

single은 acceptedChoices 길이 1, multiple은 2~4이다. 선택지 번호는 중복 없이 오름차순으로 저장한다. all_correct/excluded/unresolved는 acceptedChoices를 빈 배열로 둔다. multiple은 '여러 개를 동시에 체크'하는 UI가 아니라 한 개의 답을 골라도 인정 목록에 들어가면 맞는 공식 복수 정답 처리이다.

qa.textStatus와 qa.answerStatus는 pending/checked/hold이다. checked는 원문 또는 공식 정답표의 실제 대조를 완료했다는 뜻이며 법률 검증 표시는 아니다. 파일 형식 검사가 통과했다는 이유만으로 checked로 올리지 않는다. notes에는 미확인 사항을 기록한다.

실제 풀이 가능 조건:
dataKind=real, lifecycle=active, 두 qa 상태가 checked, officialAnswer.status=final, kind가 single 또는 multiple이고 구조 검사가 통과함. 이때 questionPdf와 answerPdf의 파일명·페이지·과목 열 근거가 모두 있어야 한다.

가답안·정답 미확인·원문 보류·특별 처리 문항도 보관·미리보기는 가능하지만 실제 풀이에서는 제외한다. all_correct/excluded의 공식 채점 특례를 임의 해석하지 않는다. 해당 회차에 이런 문항이 있으면 보관 사실과 제외 수를 표시하고, 유효 문항만 푸는 결과를 '원래 공식 총점과 동일'하다고 표시하지 않는다.

분류가 없어도 원문·정답이 검수된 문항은 회차별·과목 전체 학습에 사용할 수 있다. 단원별 학습에는 확인된 단원이, 비율형 모의고사에는 확인된 공식 출제 영역이 추가로 필요하다.

## 7. 단원 코드와 기존 목차 ID

04번 단원 등록부에는 80개 학습 단원과 형사소송법의 수사·증거 임시 대분류 2개가 있다.

- CONST-01~CONST-19: 헌법 19개
- CRIM-G-01~CRIM-G-12: 형법총론 12개
- CRIM-S-01~CRIM-S-20: 형법각론 20개. 앞서 단원 문서의 형법 번호 13~32에 대응
- POL-01~POL-29: 경찰학 29개
- CRIM-P-INV / CRIM-P-EVD: 형사소송법 수사·증거의 임시 대분류. 기본서의 새 세부 목차로 간주하지 않음

studyUnitCode는 새 학습 묶음의 고정 코드다. 기존 UUID를 대체하는 값이 아니다. 등록부 bookNodeIds의 145개 참조는 현재 GitHub main의 실제 목차 685개 노드에서 확인한 ID이다. includeDescendants=true는 해당 목차 노드의 하위 내용을 포함한다.

원래 book-taxonomies.json을 80개 노드로 덮어쓰지 않는다. 등록부는 별도 파일로 추가한다. 코드의 이름·순번을 바꾸어도 이미 배정된 코드를 재번호 매기지 않는다.

classification:
- studyUnitCode: 주 학습 단원 1개 또는 null
- relatedStudyUnitCodes: 관련 단원 코드 배열
- studyStatus: pending 또는 confirmed
- bookUnitIds: 보존할 기존 목차 ID 배열. 있으면 실제 목차에 존재하고 같은 과목이어야 함
- blueprintAreaCode: 공식 출제 영역 코드 1개 또는 null
- blueprintStatus: pending 또는 confirmed

extracted 단계에서는 classification=null로 둔다. classified 단계에서도 불명확한 값은 null/pending으로 둘 수 있다. confirmed라고 표시한 축에는 유효한 코드가 있어야 한다. 관련 단원에 주단원을 중복하지 않는다. 여러 단원 필터는 주단원+관련 단원의 합집합으로 문항을 고르고 최종 문항 ID로 중복을 제거한다.

책 목차 노드와 새 학습 묶음 연결은 검증해 두었지만, 특정 기출 문항의 주단원·공식 출제 영역은 별도 데이터 작업에서 결정한다. 기존 OX 데이터의 일부 선택지 단원만 보고 원문 객관식 전체의 주단원을 자동 확정하지 않는다.

단원 코드와 공식 영역 코드를 과목별로 교차 검증한다. 예를 들어 POL-01을 헌법 문항에, CRIM-GENERAL을 경찰학 문항에 붙이면 가져오기를 거부한다. 형사소송법 임시 대분류를 선택한 문항도 기존 목차 UUID를 만들어 채워 넣지 않는다.

## 8. 모의고사 편성 규칙

05번 시험 설정이 기준이다. 현재 활성 프로필은 po-standard-100-v1 하나다.
- 헌법 20문항·50점, 형사법 40문항·100점, 경찰학 40문항·100점
- 총 100문항·250점·100분
- 문항당 2.5점
- 헌법: 총론·기본질서 4, 기본권 16
- 형사법: 형법총론 14, 형법각론 14, 수사 6, 증거 6
- 경찰학: 경찰행정법 14, 기초이론 12, 경찰행정학 6, 분야별 경찰활동 6, 역사·비교경찰 2

공식 기준의 '내외'를 참고하여 앱의 기본 목표 수를 정한 것이다. 실제 기출이 매번 정확히 이 수라고 표시하지 않는다. 기존 기출을 단위로 선별하므로 합성 선택지나 변형 문항을 만들 필요가 없다.

후보 필터 순서: real 영역 → 검수·최종 정답·활성 상태 → 시험 종류·연도·회차 등 선택 범위 → 공식 영역 confirmed → 영역별 추출 → 원문 ID 중복 점검 → 세션 순서 확정·저장.

각 문항은 공식 영역 1개로만 집계한다. 관련 단원 수가 많아도 비율 계산에서 중복 집계하지 않는다. 같은 문항을 한 세션에 두 번 넣지 않는다. 동일 지문이 다른 시험의 별개 문항으로 재출제된 경우는 서로 다른 원문 ID이므로 별개 기출로 보존한다. 의미 유사도를 판단하여 자동 삭제하지 않는다.

영역마다 정해진 수를 중복 없이 추출한다. 부족하면 영역별 필요 수·보유 수·부족 수를 표시하고 정식 모의고사 시작을 막는다. 다른 영역으로 몰래 채우거나 같은 문제를 반복하지 않는다. 부족한 데이터로도 일반 학습은 계속 가능해야 한다.

모의고사 시작 전 연도·회차 범위와 사용 가능한 수를 보여준다. 내부 섞기는 편향 없는 Fisher-Yates 방식 등을 사용하고 확정 목록을 저장한다. 선택지 순서는 언제나 원문 그대로다. 과목 순서는 앱 기본값 헌법→형사법→경찰학이며 풀이 중 과목·문항 이동은 자유롭다.

경위 공채와 미래 과목의 편성·배점·교시는 이번 버전에서 비활성으로 둔다. 순경 설정에 과목 두 개만 추가하여 경위 모의고사라고 표시하지 않는다.

## 9. 학습·실전 모드와 오답 정의

학습 모드:
- 과목·학습 단원·원래 목차·연도·회차·대상 필터 선택
- 10/20/40/전체 또는 직접 입력한 양의 정수 문항 수
- 순서대로 또는 무작위
- 답 1~4 또는 '모르겠음' 제출 후 공식 정답과 본인 결과만 표시
- 해설·법률근거 입력칸과 표시 영역은 만들지 않음
- 제출 후 답 변경은 막고 연속 입력도 한 번만 기록
- 후보보다 많은 문항을 요청하면 실제 수를 미리 보여주고 그 수만 출제

'모르겠음'은 실제 응답이며 정답률 분모에 포함하고 복습 대상으로 둔다. 중도 종료하여 아직 보지 않거나 답하지 않은 문항은 오답 기록을 만들지 않는다.

실전 모의고사:
- 전체 100분 타이머, 답 수정·이동·검토 표시 가능
- 종료 전 정답·정오 표시 비공개
- 수동 제출 또는 시간 만료 시 한 번만 확정
- 미응답은 unanswered로 표시하고 점수는 0점. '모르겠음'과 구분
- answered/wrong/unknown/unanswered를 결과에서 구분하며 전체 정답률은 맞은 수/전체 문항 수
- 과목별 점수·총점·미응답 수·이번 오답 다시 풀기 제공
- 개인 사용 데이터로 합격 가능성·객관적 난이도·예상 합격선을 생성하지 않음

현재 gradingRevision의 가장 최근 확정 결과가 incorrect/unknown/unanswered인 원문을 자동 취약 문항으로 둔다. 이후 맞히면 자동 취약 상태는 해소하지만 이전 풀이 이력을 삭제하지 않는다. 수동 '다시 보기'는 자동 오답 상태와 독립적이며 직접 해제하기 전까지 유지한다.

원문 객관식을 틀렸다고 그 문항의 모든 OX 지문을 오답으로 표시하거나, 원문 객관식을 맞혔다고 연결된 모든 지문을 학습 완료 처리하지 않는다.

## 10. 시간·세션·저장

모의고사 시작 시 startedAt과 deadlineAt(시작+6000초), 확정 문항 ID·본문·공식 정답·gradingRevision 스냅샷, 현재 답안·검토 표시를 저장한다. 화면은 deadlineAt-현재 시각으로 남은 시간을 계산한다. setInterval 호출 횟수를 줄여 타이머를 구현하지 않는다.

실전은 일시정지를 지원하지 않는다. 새로고침·백그라운드 탭·브라우저 종료·PC 절전 중에도 실제 시간이 경과한다. 복원 시 종료 시각이 지났다면 마지막 저장 답안으로 즉시 확정하고 이후 변경을 받지 않는다. 시간 경과 후의 답 변경 요청은 이벤트 처리 시에도 차단한다.

학습 모드의 제출은 즉시 응답 기록과 위치를 원자적으로 저장한다. 실전 모드의 임시 답안 변경은 답안 상태만 저장하고, 최종 제출에서 문항별 확정 기록을 한 번 생성한다. 제출 재시도·더블클릭·새로고침으로 기록이 중복되지 않게 한다.

원문 기능에는 하나의 진행 중 세션만 둔다. 새 세션을 시작할 때 기존 이어 풀기 또는 종료를 선택하게 한다. 실제/시연과 기존 OX 세션은 저장 키와 상태를 분리하고 같은 영역의 두 탭 동시 쓰기는 잠금 또는 충돌 감지로 막는다.

이미 활성화한 원문 세션이 있으면 문제 데이터 가져오기를 그 세션 종료까지 막는다. 무응답 채점 여부는 학습 중도 종료와 모의고사 제출에서 위 정의를 따른다.

최종 기록에는 attemptId, sessionId, questionId, revision, gradingRevision, mode, response(1~4/unknown/null), expectedChoices 스냅샷, result(correct/incorrect/unknown/unanswered), answeredAt를 보존한다. 답이 없는 학습 중도 종료는 attempt 자체를 만들지 않는다.

IndexedDB에 영구 저장하며 기존 DB를 삭제하거나 origin을 바꾸지 않는다. 브라우저 저장 실패를 성공으로 표시하지 말고 재시도와 기록 내보내기를 제공한다. 저장 시각은 UTC, 화면 표시 시각은 기기 현지 시간을 사용한다.

## 11. 버전·가져오기·백업

revision은 문항의 어떤 저장 내용이 바뀌어도 증가한다. gradingRevision은 body·choices·공식 acceptedChoices 또는 kind가 바뀌면 반드시 증가한다. 단원·출처 파일 위치·메모만 바뀐 경우 revision만 증가시키고 학습 상태를 초기화하지 않는다. gradingRevision은 revision보다 클 수 없다.

과거 기록은 스냅샷 그대로 보존한다. 새 gradingRevision에 이전 정답률이나 최근 오답 상태를 섞지 않고 다시 학습 필요로 처리한다.

가져오기:
- UTF-8 JSON, 최대 20 MiB
- JSON Schema 검사와 추가 의미 검사 모두 통과 후 한 트랜잭션으로 반영
- 미리보기: 추가·갱신·동일·풀이 보류 수와 오류 경로
- 동일 ID·동일 revision·동일 내용은 재가져와도 변화 없음
- 동일 revision의 다른 내용, 낮은 revision, gradingRevision 역행은 충돌로 거부
- 문항 내용/정답 변경 시 gradingRevision 누락도 거부
- 같은 packageId의 낮은 packageVersion은 거부; 같은 버전의 다른 실질 내용은 충돌. exportedAt만 달라지고 내용이 같으면 동일로 취급
- 파일에서 누락된 문항은 자동 삭제하지 않음; 명시적인 retired로만 출제 제외
- 다른 packageId의 파일도 동일 원문 문항 ID 기준으로 병합 가능
- 원본 JSON의 선택지·본문을 자동 정정하거나 검수 상태를 임의 승격하지 않음

백업은 문제 데이터만 내보내기와 전체 백업을 구분한다. 전체 백업은 새 원문 저장소·그림·학습 기록·표시·진행 세션·설정·버전과 기존 앱에서 필요한 데이터를 빠짐없이 보존한다. real/demo 백업은 서로 다르게 취급한다.

복구 전 내용을 검증하고 건수를 보여준다. 교체 복구는 기존 내용 손실을 명시하고 확인 후 한 번에 적용한다. 실패하면 기존 상태를 유지한다. 기존 OX 백업 형식이 있으면 호환 복구 또는 명시적 버전 분기를 유지하며 새 형식으로 조용히 덮지 않는다.

## 12. 구현과 데이터 교환의 완료 조건

프로그램 Codex가 구현 후 프로젝트에 이 계약·Schema·단원 등록부·시험 설정을 함께 저장하고 계약 버전을 명시한다. 데이터 Codex는 같은 파일을 기준으로 산출물을 만든다.

첫 실제 연동은 한 회차 한 과목으로 수행한다. 데이터가 아직 없어도 프로그램은 빈 상태와 명확한 기능 시연 데이터로 끝까지 구현한다. 실제 기출을 생성하여 시연 데이터로 채우지 않는다.

## 3. 구현 목표

PC용 개인 학습 웹앱에서 기존 기출 문항을 그대로 풀게 하라. 현재 과목은 헌법·형사법·경찰학이다.

필수 기능:
- 원문 기출 JSON 가져오기·미리보기·의미 검증·병합
- 원문 4지선다 풀이: 사례·공통 조건·㉠㉡ 보기·개수형·O/X 조합형·표·그림 보존
- 과목·단원·기본서 위치·연도·회차 선택, 복수 단원 선택과 문항 ID 중복 제거
- 전체/미풀이/오답/모르겠음/다시 보기 필터, 순서대로·무작위
- 회차별 원문 풀이와 일반 학습
- 기출 재조합 모의고사: 공식 영역별 목표 수, 총 100문항·100분·250점
- 실전 답안 변경·문항 이동·검토 표시, 종료 전 정답 비공개, 자동 제출
- 공식 최종 정답 채점, 오답·미응답·모르겠음·수동 표시의 구분, 다시 풀기
- 자동 저장·이어 풀기·백업·복구·저장 실패 처리
- 빈 데이터, 분류 보류, 정답 보류, 영역별 문항 부족 안내

새 문제, 변형 선택지, 새 정답, 해설을 생성하지 말라. 선택지 순서를 섞지 말라. 원문 객관식 정답에서 개별 OX 지문의 정답을 추론하지 말라. 학습 기록만으로 합격 가능성이나 객관적 난이도를 생성하지 말라.

## 4. 데이터 구조와 호환성

신규 원문 형식은 format=police-original-questions, schemaVersion=1.0.0이다. 기존 OX Dataset은 별도 형식으로 유지한다. 신규 parser·타입·저장 영역을 추가하고 형식 판별자로 가져오기를 분기하라. 새 문항을 기존 judgments 구조에 맞추려고 해설·법률근거를 가짜로 채우지 말라.

기존 OX 데이터를 원문 객관식으로 자동 변환하여 본문·선택지를 추측하지 말라. 공식 원문 데이터는 데이터 담당 Codex가 제공한다. 데이터가 없어도 06_빈_데이터셋.json과 명백한 기능 확인용 시연으로 개발을 진행하라.

원문 문항 ID는 const_2026_2_1처럼 원문 참조 ID를 보존한다. 모의고사 표시 번호와 분리하고 기존 OX 지문 ID·UUID·기록을 변경하지 말라. 원문 기록과 OX 기록을 섞지 말라.

새 학습 단원 코드는 CONST-01~19, CRIM-G-01~12, CRIM-S-01~20, POL-01~29이다. 형소법 수사·증거는 CRIM-P-INV, CRIM-P-EVD라는 임시 대분류만 사용한다.

04번의 80개 단원과 2개 임시 대분류를 모두 등록하라. 80개 단원을 기존 book-taxonomies.json의 대체 목차로 덮어쓰지 말고 별도 학습 묶음으로 연결하라. bookNodeIds는 현재 저장소의 실제 목차에 존재하고 과목이 맞는지 확인하라. 기존 main과 스냅샷이 달라도 ID가 유효하면 차이를 보고하고 보존하라. 사라진 참조가 있으면 그 매핑을 보류하고 임의 UUID를 만들지 말라.

Schema 검사만으로 잡히지 않는 ID 계산, 선택지 번호 유일성·순서, 코드별 과목, 공식 정답 과목 열, 자산 참조·해시, 상태·버전 규칙은 별도 의미 검증기로 구현하라.

## 5. 모의고사와 타이머

05번 설정의 po-standard-100-v1을 구현하라. 공식 영역은 문항의 blueprintAreaCode로 계산하고, 기본서 단원 수나 OX 지문 수로 대체하지 말라. 영역 confirmed인 검수 완료 원문만 사용한다.

헌법 4+16, 형사법 14+14+6+6, 경찰학 14+12+6+6+2를 선별한다. 부족하면 영역별 부족량을 표시하고 정식 모의고사를 시작하지 말라. 다른 영역이나 같은 문항으로 몰래 채우지 말라. 데이터 부족은 일반 학습 기능의 구현·사용을 막을 이유가 아니다.

시작 시 문항·정답·버전 스냅샷과 실제 종료 시각을 저장하라. 새로고침·탭 비활성·브라우저 재실행·PC 절전으로 시험시간이 늘어나지 않게 하라. 종료 시각이 지나면 마지막 저장 답안으로 한 번만 제출 처리하고, 이후 입력을 차단하라. 종료 전 정답이나 정오를 노출하지 말라.

경위와 미래 과목은 설정 구조만 확장 가능하게 두고 이번에는 비활성화한다. 경위의 문항 수·배점·교시를 순경 설정으로 추측하지 말라.

## 6. 화면과 사용성

사용자가 비개발자이므로 JSON 내부 필드나 저장소 구조를 일반 풀이 화면에 노출하지 말라. 가져오기 오류 화면에서만 문제 위치와 해결에 필요한 설명을 제공하라.

권장 화면:
- 홈: 이어 풀기, 일반 학습, 회차별 풀이, 모의고사, 오답 복습
- 범위 선택: 과목·학습 단원·책 목차·연도·회차·필터·분량·순서
- 풀이: 사례·발문·보기·네 선택지, 진행 표시, 다시 보기
- 실전 풀이: 전체 타이머, 답안표·문항 이동·검토 표시
- 결과: 과목별 점수·총점, 정답·오답·모르겠음·미응답, 다시 풀기
- 데이터·설정: 가져오기·내보내기·백업·복구

PC 1280×720과 1440×900에서 긴 지문·그림·선택지를 읽기 편하게 구현하라. 키보드 1~4와 명확한 제출·이동 조작, 포커스 표시를 지원하고 버튼이 본문을 가리지 않게 하라. 시연 데이터는 모든 풀이·결과 화면에서 기능 확인용임을 명시하라. 세부 색상·간격은 일관되게 결정하되 핵심 규칙을 다시 질문하지 말라.

## 7. 권장 작업 순서

1. 기존 코드·변경사항·저장 방식·분류 ID를 확인하고 간단한 차이 분석을 기록한다.
2. 프로젝트 docs에 공통 규격을, 적절한 contracts/fixtures 위치에 Schema·단원·시험 설정을 추가한다.
3. 원문 데이터 타입·Schema·의미 검증·저장·가져오기·백업 호환부터 구현한다.
4. 빈 상태→일반 풀이→채점→오답→이어 풀기 흐름을 완성한다.
5. 단원·회차 필터, 비율형 편성, 실제 종료 시각 기반 타이머·복원을 완성한다.
6. 07번 핵심 검증과 기존 회귀 검증을 수행하고 실제 브라우저에서 확인한다.
7. 실행 방법과 데이터 담당 Codex 인계 자료를 정리한다.

데이터 부재 때문에 계획만 제출하고 종료하지 말라. 확인 가능한 환경 제한이 생기면 가능한 구현과 정적 검증을 끝내고, 실행하지 못한 검증을 실제 결과와 구분하여 보고하라. 테스트를 실행하지 않고 통과했다고 적지 말라.

qa와 officialAnswer의 모순에 관한 추가 규칙:
- real의 qa.answerStatus=checked이면 officialAnswer.status=final, kind!=unresolved, answerPdf 근거가 있어야 한다.
- real의 qa.textStatus=checked이면 questionPdf 근거와 모든 필수 그림 자산이 있어야 한다.
- demo는 status=demo, examCode=demo, 별도 demo ID만 사용하며 최종 정답표 검증으로 표시하지 않는다.
- all_correct/excluded는 보관하되 일반 채점에서는 제외한다. qa 상태가 checked라는 이유로 특별 채점 방식을 임의 적용하지 않는다.

## F. 검증 실행과 보고

필수 실행은 기존 앱의 빌드·의미 있는 단위/통합 테스트와 주요 브라우저 흐름 확인이다. 현재 package.json의 스크립트를 우선한다. 위 표의 각 행마다 별도 테스트를 만들 필요는 없으며 공통 검증기는 대표 정상·오류 사례로 묶어 검사한다. 반복 실행은 새 변경·실패·미해결 문제가 있을 때만 추가한다.

모의 데이터는 법률과 무관한 분명한 가상 문장만 사용한다. 기능 시연 표시는 풀이·결과·통계·백업에서 일관되어야 한다. 원문 확인이나 공식 정답 대조를 자동 테스트가 대신 보증한다고 적지 않는다.

개발 완료 보고에는 통과한 항목, 실제 실행한 명령/브라우저 확인, 미실행 항목, 확인이 필요한 실제 기출 연동 단계를 구분한다. 위 표를 복사하여 전부 통과했다고 쓰는 것은 완료 보고가 아니다.

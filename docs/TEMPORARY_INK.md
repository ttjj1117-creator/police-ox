# 현재 학습용 임시 필기 패치

2026-11-05 · 기준 main `635f219d57f6680110ea69b5a158864f00fd5806`.

## 바뀐 사용법

필기는 현재 페이지 실행의 현재 학습에서만 유지한다. 문항 왕복, 답 제출·해설·답안표·메뉴 열기, 홈에서 같은 학습 이어 풀기, blur·화면 복귀는 획과 undo/redo를 유지한다. 새로고침·앱 재시작에는 답안과 학습을 이어 풀더라도 필기를 복원하지 않는다. 실제 종료·최종 제출 기록이 저장된 뒤 해당 세션의 임시 필기를 해제한다. 취소·답안/종료 저장 실패에는 유지하며 기존 실제 기록 재시도를 사용한다.

이 문서가 현재 필기 수명의 기준이다. 이전 보고서의 영구 보존·정확한 배치별 복원·필기 저장 실패 시 종료 차단 조건은 이번 요청으로 폐기됐다. 문제·답안·오답·해설과 계정 동기화의 저장 정책은 바꾸지 않는다.

## 구현과 제거 범위

- OriginalApp이 InkSessionMemory를 소유한다. owner·real/demo·sessionId·questionId·내용 버전으로 구분한 문항당 단일 InkHistory를 Map에 유지한다. TTL/LRU 축출은 없다. 획 추가는 해당 이력만 변경하며 문제은행이나 전역 학습 기록을 저장하지 않는다.
- 실제 계정 또는 영역 전환은 이전 memory를 clear하고 새 instance로 교체한 다음 Provider가 읽는다. 같은 계정의 토큰 갱신·동기화 세대 변경은 memory를 바꾸지 않는다. 문항 Provider가 다시 마운트돼도 app memory에서 같은 이력을 사용한다.
- 영구 InkDocument/layouts, store.ts의 IndexedDB 저장·불러오기·쓰기 큐·실패 복구, 저장 상태/재시도 UI, 이전 배치 선택 UI를 제거했다. runtime은 옛 police-original-ink DB에 접근하거나 삭제하지 않는다. localStorage/sessionStorage/Cache/URL/파일/서버·백업·동기화 큐에 획을 넣지 않는다.
- DOM Range·정밀 배치 서명·배치 검증 대기·data-layout-pending 숨김을 제거했다. SVG는 같은 CSS 지면 좌표의 획을 그대로 그리며 크기가 바뀌어도 별도 빈 이력을 선택하지 않는다. 필요한 접촉 시점의 좌표 변환만 사용한다.
- finishPending은 진행 중 획만 원래 identity의 메모리에 확정한다. flush의 DB 대기·성공 판정을 없앴다. 종료창은 기본 취소 포커스·키보드·중복 확정 방지·실제 답안 저장 오류를 유지한다. 모든 저장 성공의 install 경로에서 완료 세션을 해제해 수동 종료·deadline·답안/이동 중 만료·재시도·원격 종료에도 동일하게 적용한다.
- clear/discardSession으로 무효화된 entry handle은 빈 이력을 읽고 늦은 수정도 거부한다. 종료 직후 unmount나 이전 문항의 늦은 포인터가 해제된 필기를 되살리거나 다음 문항에 마지막 점을 넣지 못한다.
- 물리 펜 접촉과 논리적 획 마무리를 분리했다. 키보드 도구 변경·종료 확인·캡처 소실로 획을 마무리해도 실제 up/cancel/blur 전에는 손바닥 차단을 유지한다. 번호 버튼 펜 탭·오선택 방지·손 이동·확대 차단·해설 앞 이동 버튼·답안표·독립 countdown·완료 획 memo를 보존했다.

도구에는 ‘필기는 현재 학습 중에만 유지됩니다. 새로고침하거나 학습을 종료하면 사라집니다.’를 한 번만 표시한다. 저장 모드 선택이나 필기 저장 경고는 추가하지 않는다.

## 검사

격리된 Chromium과 중립 자료를 사용했다. 사용자 실제 저장 영역이나 계정 자료를 초기화하지 않았다. 기존 Windows 호환 runner로 검사를 컴파일하고 테스트 포트만 5176으로 격리했다. 사용자 5173 origin은 바꾸지 않았다.

- 단위: 설치된 Node로 `node_modules/vitest/vitest.mjs run` 진입점, **432개 통과**. identity 분리·문항 왕복·페이지 재시작·실제 세션 해제·축출 없음·늦은 callback 차단 포함.
- 전체 Chromium: `scripts/run-e2e.cjs`의 동일 컴파일 진입점 + 설치된 Playwright CLI, **84개 통과**, 실패·건너뜀·flaky 0개. 필기 DB 접근 차단/옛 DB 원본 보존, 문항·홈 왕복 undo/redo, 답안 저장 실패/종료 취소/재시도, 종료·최종 제출·시간 만료, 새로고침 답안·deadline 보존/필기 없음, 화면 재배치 중 레이어 유지, 실제 펜 접촉 중 논리 마무리와 손 차단을 검사한다. 기존 원문/OX·문제/해설 동기화·오프라인/충돌·PWA·채점/타이머 회귀도 실행했다.
- 실제 계정 저장 대신 기존 FakeCloud를 사용해 auth/HTTP/IndexedDB/UI 경계를 검사한다. 실제 운영 계정이나 Supabase RLS를 새로 변경하지 않는다.
- 앱/도구 TypeScript(`tsc -b`, `tsc -p tsconfig.tools.json`)와 `VITE_BASE_PATH=/police-ox/ vite build` 프로덕션 빌드 **통과**. 최종 소스·PR·Actions·공개 빌드 일치는 완료 후 이 문서의 기준 앱 기록과 PR에 덧붙인다.

## 위치 오차와 배포 안내

폭·글씨·줄바꿈이 실제로 바뀌면 텍스트가 기존 낙서 아래에서 이동할 수 있다. 같은 지면 좌표를 유지하는 단순한 임시 필기이며, 문장을 정확히 추종하거나 재배치 위치 오차를 없앴다고 주장하지 않는다. 이 오차를 자동 숨김·배치 선택·획 삭제로 감추지 않는다. 실물 Galaxy Tab/S펜의 필압·손바닥·회전·체감 지연은 이 환경에서 직접 확인하지 못했다.

기존 웹 주소와 /police-ox/ base, Supabase 연결, 문제 ID·공식 정답·내용/채점 버전·학습 데이터·해설 규약·용량 제한 해제·동기화·DB/RLS는 유지한다. 진행 중 학습은 강제로 새로고침하지 않는다. 사용자가 정상 업데이트를 적용하면 페이지가 새로 시작되므로 그 시점부터 이전 필기를 복원하지 않는다. 문제·해설 재가져오기나 브라우저 데이터 삭제는 필요 없다.

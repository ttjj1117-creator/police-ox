# PC·태블릿 문제 읽기 화면

## 대상과 화면 크기

Galaxy Tab S11 기본형을 대상으로 한다. [Samsung 공식 사양표](https://news.samsung.com/global/meet-samsung-galaxy-tab-s11-series-packing-everything-you-expect-from-a-premium-tablet)는 기본형 화면을 11.0인치, 물리 해상도를 2560×1600으로 안내한다. 확인일은 2026-10-23이다. 이 물리 해상도를 브라우저 CSS viewport로 사용하지 않는다.

브라우저 도구 모음, 화면 확대, 분할 창, DeX에 따라 가용 CSS 크기가 달라진다. 기기 UA·기기명·고정 DPR을 검사하지 않고 CSS 폭과 사용자의 글자 크기 설정에 따라 배치한다. 1024px 분기, 약 50rem 읽기 열, 260px 보조 열, 48px 터치 목표와 글씨 10% 확대는 앱의 제품 설계값이다.

## 풀이 중 배치

- `OriginalApp`의 quiz 화면에서만 `is-quiz` 읽기 모드를 적용한다. 홈·학습 현황·데이터 관리·기존 OX 화면은 기존 구조를 유지한다.
- 큰 브랜드 헤더와 상시 왼쪽 메뉴를 접고 과목, 문항 위치, 남은 시간, 답안표 버튼, 작은 메뉴를 상단에 둔다. 메뉴에서 학습 홈·학습 현황·설정으로 이동할 수 있다.
- 문제 본문, 공통 제시문·보기, 그림, 네 선택지를 한 읽기 열에 표시한다. 원문 순서·문단·기호·공백은 기존 렌더링을 유지한다.
- 1024 CSS px 미만에서는 한 열을 사용한다. 좌우 바깥 여백은 16~20px이며 답안표는 버튼으로 연다.
- 1024 CSS px 이상에서는 최대 약 50rem 읽기 열과 260px 답안표의 두 영역을 사용한다. 별도의 왼쪽 메뉴 열은 없다.
- 150%·200% 글자 설정에서는 가로 폭이 넓어도 한 열과 접는 답안표로 돌아간다.
- 긴 문제는 문서 전체의 자연스러운 세로 스크롤을 사용한다. 본문·선택지를 작은 스크롤 상자에 넣거나 고정 높이로 자르지 않는다. 넓은 그림은 종횡비를 유지하며 해당 figure 안에서만 수평 스크롤할 수 있다.
- 제출·다음·종료 동작은 문서 흐름 안에 둔다. 고정 하단 막대가 마지막 선택지나 피드백을 덮지 않는다.

## 답안표와 키보드

`QuizChrome`과 `QuizAnswerSheet`는 세션을 생성하거나 타이머를 재설정하지 않는 화면 컴포넌트다. 답안표를 접거나 화면을 회전해도 동일한 세션과 문항 스냅샷을 유지한다.

작은 화면의 답안표는 이름이 있는 모달로 열리고 닫기 버튼에 포커스를 둔다. Tab·Shift+Tab은 패널 안에서 이동하며 Escape·닫기는 원래 답안표 버튼으로 포커스를 돌려준다. 문항을 선택하면 기존 문항 이동 처리를 수행하고 패널을 닫는다. 큰 화면 답안표는 모달이 아닌 보조 영역이며 100문항 목록만 가용 높이 안에서 스크롤한다.

선택지, 이동, 제출, 답안표와 답안표 문항 버튼은 최소 48×48 CSS px을 유지한다. 긴 선택지 문구는 버튼 안에서 줄바꿈하며 텍스트 선택·복사를 차단하지 않는다. 기존 키보드 1~4 선택과 별도 제출 방식은 유지한다.

## 실제 글씨 크기 측정

변경 전 측정은 2026-10-23 17:31 KST에 격리된 Chromium context, 기존 demo 자료, `settings.fontScale=1`에서 수행했다. 기존 사용자 브라우저의 기록은 변경하지 않았다.

측정 위치:

- 본문: `.original-question > .original-content`
- 제시문·보기: `.original-question > .original-statements p`
- 선택지 문장: `.original-choices button .original-content`

| 대상        | 변경 전 computed | 변경 후 실측 | 배율 |
| ----------- | ---------------: | -----------: | ---: |
| 본문        |         15.200px |     16.720px | 1.10 |
| 제시문·보기 |         14.400px |     15.840px | 1.10 |
| 선택지      |         13.920px |     15.312px | 1.10 |

통합 뒤 동일한 7개 CSS viewport에서 위 변경 후 값을 실제로 측정했으며 모두 기존의 1.10배였다. 태블릿 E2E의 `TABLET_COMPUTED_FONT_SIZES` 출력으로 재현할 수 있다. 허용 범위는 원래 값 대비 +8~12%다. 배율은 `tablet-reading.css`의 `--quiz-reading-multiplier: 1.1` 한 곳에서 관리하며 읽기 문장에만 적용한다. 글자 크기 설정을 1.1로 바꾸지 않고, transform·브라우저 zoom·본문 부모의 이중 배율을 사용하지 않는다.

본문 1.95, 제시문 1.9, 선택지 1.85의 기존 줄간격 배율을 유지한다. 200% 사용자 설정에서 목표 computed 값은 각각 33.440px·31.680px·30.624px이며 기존 설정값 2를 그대로 보존한다. 글자 설정은 현재 기기의 값이며 다른 기기의 동기화가 이 값을 덮어쓰지 않는다.

## 자동화 확인 범위

`e2e/tablet-reading.spec.ts`는 각 테스트의 독립된 브라우저 저장소에서 중립적인 가상 자료만 사용한다. 실제 법률 문제를 생성하거나 사용자 풀이 기록을 테스트용으로 추가하지 않는다.

| 구분        | CSS viewport       |
| ----------- | ------------------ |
| 세로 태블릿 | 800×1280, 960×1536 |
| 가로 태블릿 | 1280×800, 1536×960 |
| 분할 창     | 640×900            |
| PC          | 1440×900           |
| 작은 화면   | 360×800            |

검증 대상은 읽기 글씨의 실제 확대율, 화면 전체 가로 스크롤 부재, 단일/두 영역 전환, 48px 조작 영역, 긴 한국어 문단·보기·1600px 가상 그림, 마지막 선택지와 피드백, 200% 글자 설정, 100문항 답안표 포커스·이동·닫기, 회전·새로고침 전후 답안과 실제 마감 시각 보존이다. 일반 마우스 context와 터치 context를 구분한다.

2026-10-23에 기존 127.0.0.1:5173 개발 서버를 대상으로 아래 명령을 실행했으며 **4개 브라우저 사례가 모두 통과했다(9.5초)**.

```powershell
node scripts/run-e2e.cjs tablet-reading --output=test-results-tablet --reporter=line
```

7개 viewport에서 100% 읽기 글씨, 두 영역/단일 열 전환, 48px 조작 영역과 화면 전체 가로 스크롤 부재를 확인했다. 200%는 1280×800·640×900·360×800에서 확인했으며 본문·보기·선택지의 computed 크기는 각각 33.440px·31.680px·30.624px였다. 터치 context에서 1600px 가상 그림과 긴 문단, 선택·별도 제출·피드백, 100문항 답안표 열기·포커스 제한·Escape·포커스 복귀·문항 이동·닫기, 화면 회전·실제 1분 경과·새로고침 뒤 동일 답안과 deadlineAt 보존을 검사했다. 새로고침 후 표시는 임의의 로딩 시간 가정이 아니라 저장된 deadlineAt−현재 시각과 비교한다.

자동화에서 생성하는 화면은 `test-results/tablet-long-reading-800.png`, `tablet-short-reading-800.png`, `tablet-reading-200-1280.png`이다. 별도 자동화가 이 결과 폴더를 정리할 수 있으며 위 명령으로 다시 생성할 수 있다.

**확인 수준: 태블릿 viewport 자동화 확인. 실제 Galaxy Tab S11·Samsung Internet에서의 확인은 필요하다.** 이 작업 환경에 실제 기기는 연결되지 않았다. 실제 PWA 설치나 서비스 배포에서의 오프라인 재실행은 별도의 배포·PWA 검증 결과와 구분하며, 이 화면 테스트만으로 성공했다고 판단하지 않는다.

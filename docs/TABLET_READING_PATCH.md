# 갤탭 읽기·번호 선택·연필 필기 패치

2026-10-24 작성, 2026-10-26 입력 정책 정정. 원문 객관식 풀이 화면에 적용한다. 현재 자동 펜/손 입력과 최신 검증·배포 결과는 [자동 입력 정정 기록](AUTO_PEN_TOUCH_CORRECTION.md)을 따른다. OX 표시·판정 정책, 문제 데이터·정답·분류·ID, 학습 기록과 기존 동기화 계약은 바꾸지 않는다.

## 원인과 수정

- 읽기 전용 CSS가 기존 작은 본문/보기/선택지 크기에 1.1을 곱했고, 선택지에는 0.87em이 남아 있었다. 읽기 크기를 기본 22px로 통일하고 저장된 `fontScale`을 한 번만 적용한다. 480px 이하에서는 20px다. 기존 125/150/200% 값은 보존한다.
- 가로 화면의 고정 260px 답안표 열, 50rem 읽기 폭 및 1200px 조상 상한이 공간을 제한했다. 모든 폭에서 단일 읽기 열을 기본으로 하고 답안표는 요청할 때 본문 위 오버레이로 연다. 1920px의 넓은 데스크톱 상한은 태블릿 폭을 제한하지 않는다.
- 전역 `header`의 1060px 상한과 기존 question padding `!important`도 확인해 풀이 화면에서만 교정했다. 바깥과 카드 안쪽 좌우 여백은 16px, 작은 화면은 바깥 12px다. 문항 진입·이동 시 위에서부터 읽도록 스크롤을 맞춘다.
- 필기 도구는 기본 54px의 한 줄로 정리하고 긴 설명은 `필기 안내` 안에 접었다. 전역 details 여백과 필기 표면 말미의 중복 여백도 제거해 글씨를 줄이지 않고 보통 분량의 네 선택지가 가로 800px 높이에 들어오게 했다.
- 문장 전체 button을 없앴다. 고정 48×48px 번호 button과 별도 문장 DOM으로 나누고 전체 행 클릭이나 문장을 감싸는 label을 사용하지 않는다.
- 원문 텍스트에 저장된 개행은 존재하지만 문단/물리적 추출 줄바꿈을 구별하는 메타데이터가 없다. 추측해서 삭제하지 않았으며 pre-wrap, 보기 표지, 문단·그림 순서를 보존했다. 따라서 원문에 명시된 짧은 줄의 자연스러운 끝 여백까지 강제로 채우지는 않는다.

사용자 데이터가 없는 새 Chromium context의 중립적인 시연 자료로 측정했다. 브라우저 zoom이 아닌 computed font-size와 getBoundingClientRect 결과다.

## 번호·답안표·글씨 조절

- 번호를 눌러 선택한다. 일반 학습은 별도 `답 제출`을 눌러 확정한다. 문장 탭·드래그·스크롤은 선택값을 바꾸지 않는다.
- 기존 1~4 키보드 선택, 모르겠음, 제출 후 잠금, 모의고사 임시 응답 변경과 만료 채점을 유지한다.
- 모든 폭에서 상단 `답안표 n/전체`로 열고 닫는다. 100문항 이동·검토 표시·Escape·포커스 복귀를 유지한다. 열어도 본문 폭은 변하지 않는다.
- `글씨 − / 현재 크기 / 글씨 +`는 기존 설정을 저장하며 문항·임시 선택·deadline을 초기화하지 않는다.

## 연필 사용과 저장 범위

기본 도구는 `연필`이다. 문제를 열면 도구 전환 없이 펜으로 본문·제시문·보기·선택지와 사이 여백에 O/X·밑줄·빗금을 그릴 수 있다. 손가락은 필기하지 않고 이동·일반 조작에 사용한다. `지우개`를 선택해도 손가락 이동은 그대로 사용하고 펜만 닿은 획을 지운다. 실행 취소/다시 실행은 최근 50단계이며 `현재 문항 필기 지우기`도 실행 취소할 수 있다.

실제 펜 접촉 중에는 손가락·손바닥의 이동과 버튼 오작동을 막는다. 손이 먼저 움직이다 펜이 닿은 경우도 그 손 접촉을 무효화하며, 펜이 떨어져도 무효화한 손 접촉은 끝날 때까지 되살리지 않는다. 이후 새로 시작한 유효 손가락 제스처는 자동으로 스크롤·번호 선택에 사용한다. 이동·읽기 버튼이나 길게 누르는 잠금 해제 조작은 없다. 번호 위에서 움직이는 펜 드래그는 답 선택으로 처리하지 않고, 펜의 짧은 번호 탭·마우스·키보드는 선택할 수 있다. 번호·제출·다음·메뉴 버튼 위에는 필기 레이어를 놓지 않는다. 개인 O/X 표식은 답 선택이나 정오 판정에 사용하지 않는다.

필기는 별도 IndexedDB `police-original-ink`의 벡터 획이다. 기존 소유자/계정, real/demo, 세션, 문항, 렌더링 콘텐츠 버전, 정확한 배치로 구분한다. 같은 세션의 같은 문항·같은 배치에서는 이동·새로고침 후 복원한다. 새 세션에는 이전 풀이의 표식이 보이지 않는다.

글씨·화면 폭·글꼴·이미지·문장 배치가 달라지면 이전 획을 억지로 확대해서 겹치지 않는다. 별도 배치로 보관하고 안내하며 원래 배치로 돌아오면 다시 표시한다. 각 배치의 undo 기록도 분리한다. 단순 스크롤은 배치 변경이 아니므로 획이 문장과 함께 이동한다.

**필기는 이 기기에만 저장되며, 기존 일반 백업과 PC·갤탭 동기화에는 포함되지 않는다.** 문제·답안·다시 보기·학습 현황의 기존 저장과 동기화는 유지한다. 저장 완료는 IDB transaction commit 후 표시한다. 실패하면 별도 오류와 재시도를 제공한다. 이동 직후 늦게 실패한 획도 같은 앱 실행 중 원래 문항의 메모리 임시 자료로 복구하지만, 앱을 닫은 뒤까지 저장된 것으로 표현하지 않는다. 오류 안내가 있으면 닫기 전에 다시 시도한다.

## 입력·성능과 검증 한계

펜 입력은 Pointer Events로 구분한다. 획 이동은 ref·프레임 단위 SVG 갱신이며 매 pointermove마다 전역 학습 상태나 IDB를 저장하지 않는다. 획 확정 시 저장하고 문항 왕복의 미완료 쓰기도 원래 키에 직렬 처리한다. pointercancel/lostpointercapture/화면 이탈을 종료 처리하며 pressure 0 또는 coalesced events 미지원도 처리한다.

필기 표면의 제스처 정책은 접촉 전에 준비한다. 한 손가락 이동은 스크롤 가능한 조상으로 전달하고, 실제 펜 접촉과 무효화한 손 접촉을 따로 관리한다. 제스처 시작 뒤 touch-action 변경으로 이미 시작한 제스처를 해결하려 하지 않는다. 현재의 구체적인 정책·지원 범위와 결과는 [자동 입력 정정 기록](AUTO_PEN_TOUCH_CORRECTION.md)을 따른다.

자동화 pen 이벤트는 실제 S Pen의 지연·필압 감각·손바닥 거부 검증이 아니다. 실제 Tab S11·Samsung Internet에서 직접 확인하지 않았다. 완전한 손바닥 거부나 종이의 마찰감을 구현했다고 주장하지 않는다.

# 실사용 규모 성능 진단·개선

2026-11-06 · 기준 main `9b1e2eeb82572fabd364eca27c6097959a4412aa`.

## 재현 조건과 확인한 원인

실제 로컬 파일을 읽기 전용으로 확인해 별도 Chromium 저장 영역에 넣었다. 원문 1개 패키지·1,000문항·40그림·4,072,688B, 강사 해설 1개 패키지·7,090레코드·30문서·39그림·33,412,443B다. 이미지 본문 합계는 각각 101,927B·669,025B다. 운영 계정이나 사용자의 브라우저 자료는 변경하지 않았다. 초기 2종료 세션·12시도와 큰 이력 100종료 세션·600시도는 가정이다. 별도 이전 형식 해설 4.7MB는 벤치에 합치지 않았다.

Chromium 136.0.7103.25, 1280×800, 글씨 100%, CPU 제한 없는 운영 빌드와 가짜 서버를 사용했다. 같은 진단 변환의 수정 전/후를 비교했다. 클릭은 실제 입력 시작부터 저장된 피드백/새 문항 DOM까지이며 paint·INP·물리 S펜 지연이 아니다. 함수 포함 시간은 서로 합산하지 않는다. Worker는 표준 배포 빌드와 바이트가 같고 함수 계측을 넣지 않았으므로 메인의 파싱 0회를 전체 CPU 0으로 해석하지 않는다.

## 변경과 보존

- 제한된 학습 명령으로 답안·이동·표시·글씨·종료 필드만 복사한다. 저장소는 자체 트랜잭션의 자료에 같은 명령을 적용하고 generation 검사·답안/대기열 원자적 commit을 유지한다. 일반 자료 변경의 전체 비교와 진행 중 은행 변경 금지는 그대로다.
- 같은 불변 은행의 중복 비교를 줄이고, 메타데이터 전용 저장은 원문 상태를 교체할 수 없게 했다. 상태 generation과 메타 revision 충돌 검사를 유지한다. 빈 수신에도 인과 순서·충돌 계산은 보존한다.
- 실제 저장 세대에 연결한 검증된 불변 해설·fingerprint를 재사용하고, 원격 목록과 새 local 자료는 계속 확인한다. 새 JSON·원격 조각·변경 자산은 실제 검증하며 같은 버전의 다른 내용·해시 오류·동시 변경은 계속 감지한다.
- 기본 브라우저 경로의 해설 IDB 읽기·검증·해시·분할 전송을 owner별 Worker로 옮겼다. 계정/영역 전환은 취소하고 checkpoint에서 현재 계정을 확인한다. 결과는 작은 건수이며 실제 commit만 화면에 알린다. Worker 오류를 숨기거나 메인에서 자동 중복 실행하지 않는다. Worker가 없는 환경과 주입형 단위 검사는 같은 직접 core를 사용한다.
- 이미 시작된 동기화 도중 오프라인이 되는 경계를 재현해, pull/upload/push 직전과 Worker checkpoint에서 연결을 재확인했다. 확인받지 않은 event는 보존하고 같은 ID로 재시도한다. 이미 받은 서버 ack 처리는 유지한다.

문항·공식 정답·단원/문항 ID·과거 스냅샷·채점·deadline·원문/OX·해설·기기 동기화·큰 파일 정책·서버/RLS·DB 스키마를 바꾸지 않았다. 임시 필기는 같은 페이지 학습 중 문항 왕복에 유지하고 새로고침·종료 후 복원하지 않는다. 펜/손 입력·확대 차단·이동 버튼·답안표도 유지했다.

## 검증과 배포

최종 단위 473개, 앱/도구 TypeScript, `/police-ox/` 운영 빌드 통과. 오프라인 전환의 2개 단위 검사는 수정 전 실패·수정 후 통과했고, 원래 브라우저 시나리오도 3회 연속 통과했다. 최종 전체 E2E 84개 통과(실패·건너뜀·flaky 0). 배포 식별자는 완료 확인 뒤 기준 앱 문서와 연결 PR에 기록한다. Windows 브라우저 close 시간 초과는 모든 기능 단언 뒤 정리 단계에서 재현됐으며 해당 시나리오 단독 실행은 통과했다. 테스트의 가짜 네트워크 route를 먼저 해제하고 컨텍스트를 순서대로 닫게 수정했다. 기능 단언과 시간 제한은 유지했다.

실행 진입점은 `node node_modules/vitest/vitest.mjs run`, `node node_modules/typescript/bin/tsc -b`, `tsc -p tsconfig.tools.json`, `VITE_BASE_PATH=/police-ox/ node node_modules/vite/bin/vite.js build`, 저장소 `scripts/run-e2e.cjs`와 같은 컴파일을 사용하는 격리 포트 5176 Playwright 전체 검사다. 사용자 5173 자료는 초기화하지 않았다.

측정 해석은 [Chrome Performance](https://developer.chrome.com/docs/devtools/performance/reference), [긴 작업](https://web.dev/articles/optimize-long-tasks), [Event Timing](https://www.w3.org/TR/event-timing/)을 참고했다. 기존 공개 주소·로그인·서버 설정과 정상 PWA 업데이트 절차를 유지한다. 진행 중 풀이를 강제로 새로고침하지 않는다. 업데이트는 페이지 재시작이므로 기존 임시 필기를 복원하지 않는다.

실물 갤탭 확인: 진행 중 풀이를 마친 뒤 정상 업데이트하고, 해설이 긴 문항에서 제출·다음 이동과 동기화 중 S펜 필기·손가락 이동을 한 번 확인한다.

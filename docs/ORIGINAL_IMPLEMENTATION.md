## 기존 앱 조사

실제 작업 대상은 `C:/Users/INTEL/Documents/Codex/police-ox`이다. 요청 패키지에 적힌 `2026-09-19/x20/outputs/police-ox`는 이 디렉터리를 가리키는 junction이다. 현재 실제 디렉터리는 Git 체크아웃이 아니므로 Git diff/status로 사용자 변경을 판별할 수 없다. 기존 소스를 읽고 원문 기능에 필요한 파일만 추가·연결했다. 바탕화면의 예전 OX HTML 앱을 변경 대상으로 사용하지 않았다.

기존 기술은 React 19.1.0, TypeScript 5.8.3, Vite 6.3.5, Zod 3.25.67, IndexedDB이다. 설치 의존성과 기존 시험·목차·기록 구조를 유지한다. 프레임워크 교체·의존성 업그레이드·서버 추가·배포를 완료 조건으로 삼지 않았다.

## 진입과 데이터 공존

기존 `실행.cmd`를 더블 클릭하면 빌드된 `dist`를 Python 서버로 연다. 서버가 이미 실행 중이면 아래 주소를 바로 연다. 개발 실행은 기존 `npm run dev`를 사용한다. 로컬 파일의 index.html을 직접 열지 않고 같은 브라우저와 `127.0.0.1:5173`을 유지한다.

- 기존 OX: `http://127.0.0.1:5173/?mode=real`
- 원문 객관식: `http://127.0.0.1:5173/?view=original&mode=real`
- 기능 확인용 예시: 원문 화면에서 저장 영역을 시연으로 전환하거나 `?view=original&mode=demo`

같은 origin을 유지한다. 원문 객관식은 별도 타입·검증·저장 키·세션·기록을 사용한다. 기존 OX 문항 UUID, 판단 버전, 검증 상태, 목차 ID, 응답 기록은 자동 환산·삭제·재번호하지 않는다. 원문 객관식의 한 정답에서 개별 OX의 정답을 추론하지 않는다.

기존 IndexedDB `police-ox-storage`의 DB 버전 1과 `states` object store를 유지한다. OX의 `real`/`demo` 키와 원문의 `original:real`/`original:demo` 키를 분리한다. 기존 DB 삭제나 전체 초기화 없이 원문 키를 추가한다. 원문 상태는 데이터·자산·파일 버전·응답·수동 표시·세션 스냅샷·설정을 하나의 원자적 집합으로 저장하고 generation 비교로 두 탭의 덮어쓰기를 거부한다.

전체 백업은 `format="police-learning-backup"`, `backupVersion=2`이며 같은 영역의 원문 상태와 기존 OX v1 백업을 함께 보존한다. 문제 JSON 내보내기와 전체 백업을 구분한다. 복구는 구조·내용·참조 검증과 사용자 미리보기 확인 후 원문/OX 두 키를 한 readwrite 트랜잭션으로 교체한다. 이전 OX 백업은 기존 OX 화면의 v1 복구 경로를 유지한다.

## 실제 자료 연동 전 남은 일

공식 원문 기출 파일은 개발 패키지에 포함되지 않았다. 제품의 시연 데이터는 법률과 무관한 기능 확인용 가상 내용이다. 데이터 담당자가 한 회차 한 과목의 원문·공식 최종 정답표를 대조한 계약 형식 JSON을 전달해야 한다. 모의고사는 11개 영역의 확인된 유효 후보가 모두 목표 수에 도달했을 때에만 시작할 수 있다. 경위·미래 과목은 설정상 비활성 상태다.

## 가져온 문제 자료 선택 삭제 (2026-10-22 추가)

데이터·설정의 **가져온 문제 관리**에서 자료를 개별 또는 전체 선택한 뒤 **선택한 데이터 삭제 → 삭제 전 확인 → 삭제 확정**으로 제거한다. 확인 화면에서 취소하면 저장 상태를 변경하지 않는다. 연결된 가져오기 파일이 없는 보관 문제도 별도 항목으로 선택할 수 있다. 진행 중인 원문 풀이가 있으면 삭제를 막는다.

현재 선택한 실제/시연 영역의 원문 자료만 대상으로 한다. 다른 영역이나 기존 OX 자료를 지우지 않는다. 다른 남은 자료에서도 참조하는 공유 문항은 학습 가능 상태로 유지한다. 마지막 자료 연결까지 선택한 문항은 학습·복습·모의고사 후보에서 제외한다.

이전 풀이 이력과 세션의 문항·정답·그림 스냅샷은 보존한다. 이력에서 참조하는 문항은 내부 보관 후 선택 필드 `removedQuestionIds`의 학습 제외 표시로 관리하며, 이력이 없는 문항은 문제 저장 목록에서 제거한다. 해당 문항의 수동 다시 보기 표시는 해제한다. 같은 원본 파일을 같은 버전으로 다시 가져오면 제외 표시를 해제해 다시 학습할 수 있다. 이 내부 표시는 전체 백업·복구에 포함되며, 필드가 없는 이전 상태·백업도 호환한다. 확정 원문 교환 Schema와 4개 계약 파일은 변경하지 않는다.
